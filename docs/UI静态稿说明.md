## 零、第三轮：三个风格（当前版本）

用户一句「啥风格啊，我看没啥区别啊」把第二轮否了——A/B 其实是**同一套视觉语言的两种排版**，
所以看起来像同一个 app 的两个设置。第三轮换三套**视觉语言**：

| 风格 | 文件 | 一句话 | 关键特征 |
|---|---|---|---|
| 一 · 纸感 | `mock-paper.html` | 这是一张纸 | 暖白 `#F4F1EA` 底、墨黑字、砖红 `#B8472C`、**2px 细弧没有底轨**、衬线数字、**文字按钮**（主按钮一条 1px 下划线）、无渐变无阴影无发光 |
| 二 · 玻璃霓虹 | `mock-neon.html` | 这是一块发光装置 | 近黑底 + 径向渐变、荧光橙 `#FF5A3C`、进度弧**双层发光**、字重 100 的数字带光晕、**发光圆形主按钮**、玻璃片标签、悬浮玻璃导航条 |
| 三 · 系统感 | `mock-ios.html` | 这是苹果自带的 app | 系统红 `#FF3B30`、卡片 `#1C1C1E`/白、字重 600 的紧凑数字、大圆角、**分段控件**、柔和阴影、标签栏，深浅两版 |

**对比图**：`docs/shots/v05-三风格对比.png`（这张才是给用户看的）。
拼图脚本 `scripts/make-compare.py` 用 Pillow 拼，不用 HTML+iframe——
三个并排是 1440px 宽，窗口开到 1560 在小屏上会被屏幕裁掉，`capturePage` 只拿得到可见区域。

**和方案的出入（两条，都要拍板）**：

1. **纸感数字 120px → 104px**：120px 的衬线数字两端会**压到细弧上**
   （圆在数字高度处的弦比直径窄）。104px 是能塞进弧里的最大值。
2. **系统感环 290px、数字 88px**（方案没写环径）：88px 字重 600 的数字宽约 240px，
   环小于 290px 数字就会出弧。

**420×560 全部不压叠**（实测）：纸感环 299、霓虹环 256、系统感环 240，
导航条底边都落在画板底边以内，"环是否溢出容器"三个都是否。

## 二、颜色从哪来（重要）

- **深色底直接链的是真的 `src/renderer/styles/tokens.css`**（`<link rel="stylesheet">`），
  所以稿子里的颜色没有一个是我自己编的。

  tokens.css 目前只有深色一套，也没有 `--ink-3`。
  **真要采纳这一版，第一件事就是把这两块并进 tokens.css，然后删掉 mock-tokens.css。**

## 三、怎么拍照

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue   # 这台机器预置了它
node_modules\.bin\electron.cmd scripts\shot-mockup.mjs <html> <out.png> [宽] [高] [查询串]
```

例：

```powershell
node_modules\.bin\electron.cmd scripts\shot-mockup.mjs docs\mockups\mock-a.html docs\shots\v05-A-主界面-深色.png 560 700 "screen=main,theme=dark"
```

`scripts/shot-mockup.mjs` 是新加的开发期工具：起一个无边框 electron 窗口加载稿子，
`capturePage()` 抓一张图存盘，然后退出。

**为什么不用浏览器**：项目里已经装了 electron，不用再引 puppeteer/playwright；
`capturePage` 出来的图尺寸与 DPI 都准，不会像 `PrintWindow` 那样按 DPI 放大后被裁掉。

**两个踩过的坑**：

1. 查询串用**逗号**分隔，不用 `&`——`&` 在 `.cmd` 里会被 cmd 拆开，
   报 "operable program or batch file"。
2. 这台机器预置了 `ELECTRON_RUN_AS_NODE=1`，不清掉 electron 会退化成纯 Node，
   报 "bad option"。`scripts/dev.mjs` 里也清同一件事。

## 三之二、量布局：`scripts/mock-measure.mjs`

眼看不出来的靠量：

```powershell
node_modules\.bin\electron.cmd scripts\mock-measure.mjs docs\mockups\mock-a.html "screen=main,theme=dark" [画板高度]
```

第三个参数会把画板高度改成指定值，用来验"窗口再矮会不会压叠/裁切"。
它打印每个区块的实际 `x/y/w/h`、环的上下留白，以及**环是否溢出容器**。

量出来的东西（480×620，A 版）：

```
.top       y=41  h=34
.ring-area y=75  h=401
.ring      y=128 h=322      ← 环
.controls  y=476 h=72
.status    y=566 h=39
.nav       y=605 h=56
环上下留白: 上=87 下=211    （"下"含按钮+状态行+导航，所以不代表不均衡）
环是否溢出容器: 否
```

**量出来才知道的坑**：`height: min(100%, 322px)` 这种写法在外层是 **grid** 时，
百分比解析不了（grid 行高不确定），高度会退回 SVG 的默认 `300×150`——
不量的话只会看到"环怎么变成 300 了"。改成 flex 容器后百分比才正常解析。

## 五、跟方案的出入（都要拍板）

1. **环直径**：方案里 A 版 ≈320、B 版 ≈340。两版都取 **最大 322**，
   实际尺寸 = `min(可用高度, 322)`——**随窗口高度缩**，不是写死的。
   原因有两条：
   - 420×560 时固定 340 会**压叠**（硬要求第 2 条）；
   - 写死 322 的话，**画板比约 543px 更矮时环会溢出被裁，底沿变成一条平线**。
     现在改成随高度缩，量过了：620 → 322、560 → 289、500 → 205、460 → 更小，
     **任何高度都不溢出**（`mock-measure.mjs` 的"环是否溢出容器"始终为否）。
2. **画板尺寸**：稿子是 480×620，但方案里画的是 620 高。我按 620 出的图
   （现在这个窗口默认 480×580，620 是给"以后能拖大"留的余量）。
3. **浅色底和 `--ink-3` 的去处**：现在在 `docs/mockups/mock-tokens.css`，
   实现时并进 tokens.css 并删掉它。

## 六、A 版的垂直节奏（480×620 实测，单位 px）

```
顶栏 34 → 环上 52 → 环 322 → 环下到按钮 24 → 按钮 72
→ 按钮到状态行 18 → 状态行 17 → 状态行到导航 24 → 导航 56
```

上下留白对称，重心落在窗口中线略偏上（下面有状态行和导航压着）。
状态行原来贴着导航的分隔线，现在离 24px。

## 七、时间数字的冒号

`tabular-nums` 会把冒号两侧的字宽撑开。实测（96px 字号）：

```
"1" 墨迹 146.3–181.7   "8" 190.3–228.3   ":" 237.0–243.7   "4" 249.0–292.3
数字间距 8.6px，冒号左边 8.7、右边 5.3
```

不修的话读起来像「18: 42」。修法：冒号单独一个 `span`，`margin: 0 -0.035em`
把两侧收回来。改完整串宽度 198.3 → 191.6px。

## 八、B 版的三处参数调整

1. **进度弧渐变收一收**：末端从 `55% accent + 45% 白` 改成
   **`85% accent + 15% 白`**（原来走到一半以后对比明显变弱、发白发粉）。
2. **发光收一收**：环后光晕 9% → **6%** 且半径收窄；环内柔光保持 **8%**
   但贴住边缘（透明起点 62% → 76%），不再往中间糊。
   质感靠边缘清晰 + 一点点光，不靠糊。
3. **模板 chips 去掉时长**：`经典 · 25/5` → `经典`。
   切模板时你看的是"哪个"，不是"多少分钟"；时长留在设置页和当前值上。

## 九、没做的

- **灵动岛没出稿**：方案说"结构不动，只把圆角/颜色跟新版对齐"，
  那属于实现阶段（改 tokens 就够了），不是设计选择。
- **没做交互和动画**：抽屉滑出、阶段切换的交叉淡入都只是方案里的文字，
  这轮不出稿。
