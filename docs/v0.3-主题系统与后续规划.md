## 一、毛玻璃与圆角的定案：二选一，我们选圆角

### 技术事实（小M 实验得出）

- `backgroundMaterial: 'acrylic'` 的材质**铺满整个窗口矩形**，CSS 的 `border-radius` **裁不住它**——圆角只裁内容，材质照旧铺满。
- `win.setShape()` **只裁内容不裁材质**，也救不了。
- 所以想要真亚克力，形状就只能由窗口本身给：要么 Win11 的 DWM 圆角（**固定约 8px，四角同时圆，还不能单独控制**），要么老老实实一个直角矩形。

### 结论

**选圆角，放弃真亚克力，走透明窗口 + CSS 圆角 + 伪毛玻璃。**

理由：
1. 用户两次提出的核心是"像灵动岛"。灵动岛的识别性就在形状上——**大圆角、胶囊感**，8px 圆角的小矩形根本不是那个东西。
2. 灵动岛还要展开/收起变尺寸。只有 CSS 能做出连续顺滑的形变；靠改窗口尺寸走 DWM 圆角，动画必然是一跳一跳的。
3. 伪毛玻璃能到九成观感（做法见下），真亚克力只多一成，但要拿形状和动画去换，不划算。

### 伪毛玻璃的具体做法（这是验收标准，不是形容词）

必须四层叠加，少一层就不像玻璃：

1. **底色**：`rgba(16,18,22,0.72)`——半透明，能让壁纸透一点上来
2. **噪点**：内联 SVG `feTurbulence` 生成的静态噪点，`opacity: 0.035`，`mix-blend-mode: overlay`。**这层是"像玻璃"的关键**，没有它就是一块半透明塑料
3. **高光**：顶部 1px `rgba(255,255,255,0.10)`；下沿 1px `rgba(0,0,0,0.35)`
4. **内阴影**：`inset 0 1px 0 rgba(255,255,255,0.06)` + `inset 0 -1px 0 rgba(0,0,0,0.25)`，制造厚度

外加一条：整体加 `box-shadow: 0 8px 24px rgba(0,0,0,0.45)`，用窗口留的 14px 透明余量。

**验收方法**：把岛放到深色壁纸和浅色壁纸两种桌面上各截一张图。如果浅色壁纸下它糊成一片灰、看不出边界，就不合格。

## 二、圆角定案

用户要"尽量圆角"，那么：

- **收起态** 172 × 34：下边圆角**最大到 17px（半高）**，即下沿呈半圆——这是最像灵动岛的形态，优先做这个。
- 上方两角保持直角，因为窗口贴死屏幕顶端，上沿被屏幕边框吃掉，视觉上没有上角。
- **展开态** 344 × 76：下边圆角 20px，不再用半圆（半高 38px 太大，会显得像面包）。
- 圆角随高度变化要跟着算，不要写死。

如果半圆下沿在实际屏幕上看着怪（比如壁纸亮的时候像一条舌头），退一步用 14px 圆角，让用户看图拍板。

## 三、v0.3-a：计时模板（用户补的新需求）

用户原话：「番茄钟的时间我需要可以自己调整，可以就是默认一套模板，然后可以自定义模板，专注时间、间隔时间」

现在设置页已经有四个数字输入框了，但那只是"改参数"，不是"模板"。差别在于：改参数会把唯一那套设置覆盖掉，模板是**可以来回切的几套**——上午写代码用 50/10，下午开会间隙用 15/3，切一下就换，不用重新调数字。

### 内置模板（不可删，可复制）

| 名称 | 专注 | 短休 | 长休 | 几轮长休 | 适用 |
|---|---|---|---|---|---|
| 经典 | 25 | 5 | 15 | 4 | 默认，番茄工作法原版 |
| 深度 | 50 | 10 | 25 | 3 | 写代码、写文档这类进状态慢的活 |
| 冲刺 | 15 | 3 | 10 | 4 | 间隙时间、处理零碎事 |
| 考试 | 45 | 10 | 20 | 2 | 需要长时间连续专注的 |

内置的这几个不要给太多，四个够用。给太多会让人花时间比较模板而不是干活。

### 自定义模板

- 字段：名称、专注分钟、短休分钟、长休分钟、几轮后进长休
- 操作：新建、编辑、复制（基于现有模板改）、删除（内置的不能删，但能复制成自定义）
- 名称必填，上限 12 字，重名给提示
- 时长范围约束：专注 1–180 分钟，短休 1–60，长休 1–90，轮数 1–12。**超范围直接拒绝并说明**，不要静默截断

### 切换规则（跟已有规则保持一致）

- 有一个"当前模板"，在灵动岛展开态和主界面都能切
- **计时进行中切模板：只影响下一段，当前段的时长不变**——跟"改时长只影响下一段"同一条规则
- 切模板时如果正在跑，给一句轻提示（"下一段生效"），别让人以为立刻变了
- 默认模板由用户在设置里指定，新装时是"经典"

### 数据模型

```ts
type Preset = {
  id: string;
  name: string;
  focusMin: number;
  shortMin: number;
  longMin: number;
  roundsBeforeLong: number;
  builtin: boolean;
  order: number;
};

// Settings 改造
type Settings = {
  activePresetId: string;   // 替代原来的 focusMin 等散字段
  presets: Preset[];
  // ... 其余不变
};
```

迁移：`schemaVersion 2 → 3`，把老的 `focusMin/shortBreakMin/longBreakMin/roundsBeforeLong` 打包成一个自定义模板（名为"我的设置"），并把它设为当前模板。老用户打开还是原来的时长，不被打断。迁移必须幂等。

### 一个容易做错的细节

休息段结束后自动进入下一段专注时，**必须读"下一段开始时"的当前模板**，而不是这一段开始时的。因为用户可能在这段休息里切了模板。这条在实现时容易写错成缓存初始值。

## 四、v0.3-b：主题系统（这是本轮重点）

用户说的"任务主题"，本质是**项目/分类**，不是待办清单。两者的区别很重要：

- **待办清单**：一条条要做的具体事，有完成状态、有优先级、有截止时间。（**我们不做**，太重）
- **主题**：一个长期存在的归类空间，比如"写代码""写报告""学英语""改 bug"。番茄钟挂到主题上，时间就归到主题上。（**我们做这个**）

这个区别决定了它不会把产品做成 TickTick，也就守住了"少而准"的边界。

### 功能定义

**主题本身**

- 增 / 改名 / 归档（不删除，归档后不再出现在选择器里，历史数据保留）
- 每个主题：名称、颜色（从调色板里选，不自由取色）、创建时间、排序
- 首次启动预置 3 个示例主题？**不预置**——空着更好，用户自己建第一个，避免一堆用不上的默认值

**计时与记录**

- 灵动岛展开态有一个"当前主题"，点一下就地切换
- 主界面开始前选主题；**允许为空**（记为"未分类"），不强制选择——强制会让人为了开始计时而先建主题，这是劝退
- 一段番茄结束，`Session` 带上 `topicId`
- 中途切主题：**只影响下一段**，当前段不变（跟时长规则一致）
- 休息段不挂主题

**统计（这是用户要的核心价值）**

- 主题时间占比：横条排行，按本周 / 全部两个口径
- 每个主题：回合数、总时长、平均每回合时长、**打断率**
- 今日概览：“今天 3 个主题、6 个番茄”，按主题分组

**边界（明确不做）**

- 不做子任务、不做截止时间、不做完成状态、不做优先级、不做提醒、不做看板
- 不做标签系统（主题已经够了，两个分类体系会打架）

### 数据模型

```ts
type Topic = {
  id: string;
  name: string;
  color: string;      // 从固定调色板取
  archived: boolean;
  createdAt: string;
  order: number;
};

// Session 增加两个字段
type Session = {
  // ... 原有字段
  topicId?: string;      // 为空 = 未分类
  topicNameSnapshot: string; // 记录当时的主题名，改名后历史仍可读（可选）
};
```

迁移：老数据 `schemaVersion: 1` → `2`，给所有历史记录补 `topicId = undefined`（即"未分类"）。迁移要幂等，跑两次不能重复处理。

### 市场参照（回应用户"应该也有类似功能"）

- TickTick：清单 = 项目，番茄钟挂清单，这是它的核心卖点
- Pomofocus Premium：项目分类 + 每项目报告，这正是它收费项之一
- Toggl Track：项目维度的时间统计，是时间追踪类的标准做法

**结论**：功能不新，但**"主题 + 番茄 + 桌面常驻 + 打断率"这个组合没人做**——尤其打断率，主流产品都不给。这是我们能做出差别的地方，不靠功能多，靠统计诚实。

## 五、v0.4：音乐控制（单独立项，先做可行性探针）

用户说"如果可以的话，当前这一轮也可以先不做"，我判断：**要做，但不能和主题系统挤在一轮**，且必须先验证技术可行性再承诺。

### 为什么危险

Windows 上要拿到"当前在放什么歌、播/暂停/下一首"，唯一通用路径是 **SMTC（System Media Transport Controls）**，也就是系统音量栏那个播放控件的同一套 API。它是 WinRT 接口（`Windows.Media.Control`），**Electron 没有原生绑定**。

### 三条可能路线

| 路线 | 做法 | 风险 |
|---|---|---|
| A. PowerShell 探针 | 用 PowerShell 调 WinRT 查询 SMTC 会话，Node 侧起子进程读 | 需要长期驻留子进程；PowerShell 调 WinRT 语法恶心；性能一般（每 2 秒轮询） |
| B. C# 小程序 | 编译一个小 exe 做 SMTC 服务，通过 stdio 和主进程通信 | 要维护第二个二进制；但最稳、最省 CPU |
| C. 第三方播放器 API | Spotify Web API 等 | 要 OAuth，只覆盖一家，国内播放器基本没有公开 API |

### 建议的探针（限时 20 分钟，先不写进产品）

在 PowerShell 里跑一次：能不能枚举到当前媒体会话、拿到标题/艺术家、能不能发 play/pause。**能拿到再谈实施，拿不到就直接告诉用户"这条做不了"**，别耗几天做出个半成品。

如果探针通过，实施形态定为：灵动岛展开态底部一行"♪ 歌名 - 歌手" + 三个按钮（上一首 / 播放暂停 / 下一首），只做控制不做播放。收起态不显示（避免拥挤），或者只在展开时出现。

**不做**：内置播放器、音量控制、歌单、歌词、任何和音乐库相关的功能。
