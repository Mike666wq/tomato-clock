## 二、修了什么，怎么修的

### D1｜并发保存设置会互相覆盖 → 设置单例 + 串行队列

**修法**：新增 `src/main/store/settings-store.ts`。

- 主进程只存**一份**设置（内存单例），读不读盘都读它；
- 所有写入进**一条 Promise 队列**，一个接一个做，不会重叠；
- 合并用的是队列里**当前的内存值**，不是磁盘上的旧快照；
- 落盘前**先校验**，不合法就整份拒绝。

```ts
save(patch: Partial<Settings>): Promise<Settings> {
  return enqueue(async () => {
    const current = await settingsStore.init()
    const next: Settings = { ...current, ...patch }
    ...
    await jsonStore.saveSettings(next)
    cache = next
    return next
  })
}
```

**验收**：并发写两个不相干的字段（主题 + 音量），**连续 20 轮零丢失** —— `D1 并发保存两个不相干的设置：20 轮零丢失 :: 20 轮都没丢`

### D2｜拖窗口把设置顶回去 → 只写 window，而且走同一条队列

**修法**：`src/main/index.ts` 的 `saveBounds` 改成只提交 `window` 一个字段，
合并由队列里的合并逻辑做（用的是内存里的当前值，不是快照）。
另外加了 300ms 防抖 —— 拖一次窗口会连着触发几十次 resize/move。

**验收**：用真的 Win32 调用把窗口拖 20 次（`scripts/resize-window.ps1`），
之后主题/音量/模板都还在 —— `D2 拖窗口 20 次后，主题/音量/模板都还在 :: 主题=ios 音量=0.77 模板=builtin-classic；RESIZED 20`

### D3｜「今天」两套口径 → 只允许一处实现

**修法**：新增 `src/shared/day.ts`：

- `localDateKey(d)`：本地日期 → YYYY-MM-DD
- `sessionDayKey(startedAt)`：**按开始时间**归属（规格第四节）
- `isToday(startedAt, now)`
- `msUntilNextMidnight(now)`：距离下一个零点还有多少毫秒

`buildSummary`（主界面）和 `buildStats`（统计页）现在都调 `sessionDayKey`，
口径不会再走偏 —— "两处各算一遍"就是那次 bug 的根源。

**验收**：
- `D3 跨零点的番茄：主界面与统计页给出同一个数 :: 主界面=1 统计页=1（旧口径按结束时间算是 2）`
- `D3 跨零点的番茄：不计入今天（按开始时间属于昨天） :: 今天=1 期望=1`
- 单测 `D3-2 记录按开始时间归属某一天`

### D4｜跨零点不刷新 → 拉取式 + 获得焦点 + 零点定时器

**修法**（三处触发，缺一不可）：

1. **拉取式**：`src/renderer/pages/Timer.tsx` 进页面拉一次 `records.summary()`；
2. **窗口获得焦点**：渲染层监听 `window` 的 `focus` 事件再拉一次 ——
   用户从别的程序切回来，看到的必须是现在的情况；
3. **跨零点**：主进程算到下一个零点的毫秒数，`setTimeout` 到了就重算并推一次
   （`msUntilNextMidnight`），**不用轮询** —— 一个自用工具不该每 5 秒醒一次。

**验收**：`D4 跨零点后主界面归零，且与统计页一致 :: 跨零点前=1 跨零点后 主界面=0 统计页=0 状态行=0`

> 这一条怎么测的：主进程有一个**可注入的时钟**（`src/main/clock.ts`），
> 测试把"现在"推到第二天 23:59:55，等它真的跨过零点。
> 计时器用真实时间（它要秒级准确），只有"今天是哪天"用注入的时钟。
> 注入口子是**开发期专用**（`import.meta.env.DEV`），打包产物里没有。

### D5｜坏值写盘 → 校验 + catch + 提示 + 不落盘

**修法**：

- 新增 `src/shared/settings-schema.ts`：写盘前校验整份设置
  （主题/深浅/模板/主题列表/音量/开关/窗口位置）；
- `settings:save` 的 handler 全部包 `catch`，失败走 `pushNotice`；
- **校验不过就抛错，一个字节都不写**；
- 顺带修了一个自己踩出来的坑：删掉"正在用的那个模板"时，
  界面会先发"模板列表变了"、再发"换个模板"，中间那一刻
  `activePresetId` 指向已经不存在的模板 —— 那是正常状态不是坏数据，
  存储层会把它修正掉，而不是把整次保存拒了（有专门的断言守着）。

**验收**：
- `D5 传一个坏值：磁盘文件一个字节都没变 :: 前 2265 字节 / 后 2265 字节`
- `D5 传一个坏值：界面上有提示 :: ["设置没保存：界面主题不认识（123）"]`
- `D5b 删掉正在用的模板：删除生效了，且没有报错`

### D6｜仓储层 → 唯一临时名 + 读坏改名备份 + 提示

**修法**（`src/main/store/json-store.ts`）：

- **所有写排队**：`addSession` / `updateSession` / `saveSettings` 都进同一条队列，
  一个接一个做，不会重叠（这是丢记录的根因）；
- **临时文件名唯一**：`.tmp` → `.<pid>.<序号>.tmp`，谁也撞不上谁；
- **读不出来不再静默**：改名备份成 `data.json.corrupt-<时间戳>` + 记 ERROR +
  推一条提示给用户，**不许**静默当默认数据。

**验收**（`corrupt` 段，手工把 `data.json` 写坏后重启）：
- `D6 数据文件坏了：程序没崩，照样能取到状态`
- `D6 数据文件坏了：原件被改名备份了 :: data.json.corrupt-1795428566485`
- `D6 备份里就是那份坏文件（没被覆盖）`
- `D6 数据文件坏了：日志里记了 ERROR`
- `D6 运行中读到坏文件：界面上立刻有提示 :: ["数据文件损坏，已备份为 data.json.corrupt-1795428566882"]`

## 三、新架构（这一轮改了什么）

```
主进程
  ├── clock.ts            可注入的时钟（只有"今天是哪天"用它；打包产物里没有入口）
  ├── store/
  │     ├── json-store.ts   所有写排队 + 唯一临时名 + 读坏改名备份
  │     └── settings-store.ts  设置单例 + 串行写入队列 + 写盘前校验
  └── index.ts           设置读写全部走 settingsStore；跨零点定时重算

shared
  ├── day.ts             「今天」的口径（只此一处实现）
  └── settings-schema.ts 设置的结构校验
```

**不变的规矩**：

- 颜色只在样式层；
- 组件里不为某个主题写 if；
- 计时状态归主进程；
- 打包产物零开发期入口（`import.meta.env.DEV` 的几段都会摇掉）。

## 四、端到端脚本怎么跑

```powershell
# 1) 起一个独立实例（别用用户正式版，它正开着会撞单实例锁）
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
$env:POMODORO_USER_DATA = "<项目>\.tmp\e2e"
pnpm dev

# 2) 跑旅程
node scripts\e2e-journey.mjs

# 3) 崩溃恢复：强杀进程 → 重起 → 再跑
$env:E2E_STAGE = 'restore'
node scripts\e2e-journey.mjs

# 4) 数据文件损坏：写坏 → 杀 → 重起 → 再跑
$env:E2E_STAGE = 'corrupt'
node scripts\e2e-journey.mjs
```

**三个环境坑（都是踩过的）**

1. `pnpm exec electron-vite dev -- --user-data-dir=...` 会报
   `CACError: Unknown option --userDataDir` —— electron-vite 的 cac 不接受这个开关。
   而 `ELECTRON_CLI_ARGS` 这条路在本次也没生效（`.tmp\e2e` 目录是空的，
   说明 Electron 根本没收到这个参数，仍然用了默认 userData，于是跟用户正在运行的正式版
   撞了单实例锁，**静默退出、退出码 0、没有日志**）。
   最后用的是**开发期专用环境变量** `POMODORO_USER_DATA`：
   主进程在 `requestSingleInstanceLock` 之前 `app.setPath('userData', ...)`。
   这个口子被 `import.meta.env.DEV` 包着，**打包产物里没有**。
2. 打包版启动前必须 `Remove-Item Env:ELECTRON_RUN_AS_NODE`，
   这台机器预置了这个变量，Electron 会被强制当成纯 Node 跑。
3. `scripts\resize-window.ps1` 必须是**纯 ASCII**：
   Windows PowerShell 5.1 在没有 BOM 时按 ANSI 读 .ps1，中文字面量会把解析器搞挂。
   而且不能用 `FindWindow` 找窗口（标题走 ANSI 通道，中文永远匹配不上），
   改成了「枚举进程下的窗口 + 按尺寸认主窗口」。
   C# 源码也不能用 here-string（换行会被吃掉），改成数组拼接。

  下一版值得把记录单独拆一个文件。

  这一轮压测里反复并发提交，没丢（仓储层已经排队了），但值得再压一轮更大的量。
