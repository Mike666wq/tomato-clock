# v0.6.2 用户反馈三条（灵动岛 / 统计页 / 音乐行）

> 2026-11-23 ｜ 用户装了 0.3.1 之后提了三条：
> 「未分类这里不要有了，提示可以创建主题就行了」
> 「统计这里逻辑不完整，UI也不完整」
> 「音乐这里最好也做完善一点，现在这里显示太小了」
>
> 这一版是 0.3.2。

---

## 一、灵动岛：不再有"未分类"这个伪选项

**为什么改**：「未分类」是**数据概念**（这条记录没挂主题），不是能选的东西。
摆出来会让人以为"未分类"是个主题，可它其实是"没选"。

**改成什么**

| 场景 | 之前 | 现在 |
|---|---|---|
| 没选主题 | `未分类` | `＋ 主题`（--ink-3、虚线描边、比正常胶囊窄），点它 → 打开主窗口的主题分区 |
| 选了主题 | `● 主题名` | `● 主题名`（不变） |
| 想取消选择 | 点「未分类」 | **再点一次已选中的那个** |

**数据层面一点没变**：没选就是没选，记录里 `topicId` 为空。
统计页里那个「未分类」分组**保留**（历史记录得归位），但选择器里不再出现这个词。

主窗口的主题行同样处理：没有「未分类」选项，末尾多一个「＋ 主题」，
点它切到设置页并滚到主题那一块。

> 顺带解决了一个信息缺口：这一段没挂主题、但用户选了别的主题时，
> 主题行末尾会有一行小字「本段没挂主题」——
> 以前那个「本段」标记长在「未分类」上，选项没了就没人知道这段会记到哪。

## 二、统计页：四块固定存在，空态也占地方

**为什么改**：用户说"统计这里逻辑不完整，UI也不完整"。
根因有两条：

1. **整块消失**：以前"没有记录"时整个页面换成一句空态，
   卡片一块都不渲染 —— 用户会以为功能没做，而不是"还没数据"；
2. **三张数字卡长得不一样**：「今日番茄」没有单位，
   另外两张把「分钟」挤在数字右边，视觉上三张卡不是一个东西。

**改了什么**

1. **三张卡同构**：数字（大字）+ 单位（小一号，跟在数字后面）+ 标签（最下面），
   等宽等高。「今日番茄」补上了单位「个」。
2. **各板块固定存在**，没数据就在卡片里居中一行 12px `--ink-3` 的空态文案，
   卡片高度不低于 88px。空态文案：

   | 板块 | 空态文案 |
   |---|---|
   | 今日按小时分布 | 今天还没有完成的番茄 |
   | 近 7 天趋势 | 最近 7 天还没有专注记录 |
   | 主题时间占比 | 还没有挂主题的番茄 |
   | 打断原因排行 | 还没有记录 |
   | 今日概览 | 今天还没有完成的番茄 |

3. **图表加了最大值参考线**：一条极淡的虚线 + 右上角小字「最高 N 分钟」。
   只有一根柱子的时候，没有参照就不知道它到底有多高。
4. **柱子对齐**：柱子中心和刻度文字用**同一个 slot 中点**算出来的
   （以前是两处各算各的，容易差半格）。改完量过：11/20 那根柱子正好在 11/20 上。
5. **主题时间占比**每行补了分钟数（主题名 · 分钟数 · 占比），
   打断率百分比保留。

## 三、音乐行：行高 34px，歌名歌手分开

**为什么改**：11px 的字挤在 24px 高的一行里，看着像注脚。

**改了什么**

| 位置 | 之前 | 现在 |
|---|---|---|
| 行高 | 26px | **34px** |
| `♪` 图标 | 11px | 14px（`--ink-3`） |
| 歌名 | 11px，和歌手挤在一段 | **13px**（`--ink`） |
| 歌手 | 同上 | **12px**（`--ink-3`） |
| 三个按钮 | 20×20、图标 14px | **28×28**、图标 16px、按钮间距 4px |
| 播放状态 | 有图标但太小看不清 | 播放中 `❚❚`、暂停 `▶`，16px |
| 换歌 | 整行重排地闪 | 歌名/歌手段 120ms 淡入（key 跟着歌名走） |
| 长歌名 | 尾部省略号，**把歌手名吃掉了** | 歌名和歌手分成两个元素：**歌名截断，歌手永远留着** |

没有音乐在放时整行消失（这条原来是对的，守住了）。

灵动岛展开态带音乐行时的高度从 118px 改成 126px（`ISLAND.expandedHMusic`
和 `--island-h-expanded-music` 两处一起改），主进程和渲染层共用同一份尺寸。

## 五、这轮踩的三个坑

### 1. 别删 React 管的节点

截图脚本里为了不让提示条盖住数字卡，写了 `document.querySelector('.toast')?.remove()`。
结果 React 之后还要动那个节点，抛
`Uncaught NotFoundError: Failed to execute 'removeChild' on 'Node'`，
**整棵界面树当场卸载**，拍出来是一片空白（还以为是程序崩了）。

改成 `style.display = 'none'` —— 节点还在，React 的对账不受影响。

> 这条值得记：自动化脚本改动 DOM 时，
> 只能改样式和属性，**不能把 React 管理的节点从 DOM 里摘掉**。

### 2. 设置不能直接改文件

主进程把设置**缓存在内存里**（v0.6 的设置单例），统计页读设置也是从内存拿的。
截图脚本一开始直接改 `data.json` 里的 `settings`，结果界面完全不知道：
统计页把有主题的记录全显示成「未分类」（因为内存里的主题列表还是空的）。

记录可以直接写磁盘（统计页每次都重新读文件），
**设置一律要走应用自己的 `settings.save`**。

### 3. 统计页内容滚在内层容器里，整页拍不到

`captureBeyondViewport` 只对文档级滚动有效，
统计页滚的是 `.main--page` 这个内层容器 —— 拍出来永远只有首屏。

改用 `Emulation.setDeviceMetricsOverride` 把视口拉高到 1120px，
一屏装下全部内容再拍。

## 六、没动的地方

- **数据层面**：主题的记录归属、"没选就是没选"完全没变；
  统计页的「未分类」分组保留。
- **逻辑**：这一版只改界面和一段交互，没碰计时逻辑。
  端到端 33 项断言重跑全绿（`docs/logs/e2e-journey-v0.6.log` 那套）。
- **打包产物零开发期入口**：这轮加了两个开发期口子
  （`POMODORO_USER_DATA`、`media:dev-fake`），都被 `import.meta.env.DEV` 包着，
  打包产物里搜不到（0.3.1 那次已经验过同样的做法）。
