## 这轮的大规矩：像素问题不许目测

肥鱼这轮立了一条规矩，我把它当成这轮的验收标准：

> **判断像素对齐必须用 `mock-measure` 或 DOM 边界量，不许看截图说"歪了"。**

理由是他自己栽过：他说"11/22 那根灰柱明显偏左"，实际量下来两处本来就是同一个算法、
柱子是对齐的。缩略图缩放后一根柱子差两三个像素完全看不出来。

这条规矩不只对图表适用 —— **本轮所有的视觉修复，证据都是量出来的数字**，
脚本在 `scripts/measure-v063.mjs`，10 项断言。

### 量出来的一个反直觉结论

肥鱼说「纸感下虚线太淡，提到 `--line` 的正常不透明度」。
我按他说的量了一下 `--line` 满不透明在纸底上的对比度：**1.20:1** —— 肉眼等于看不见。
所以没照抄，改成墨色和 `--line` 混一档，实测 **3.32:1**。

**结论不是"按肥鱼说的做"，是"按肥鱼的目标（线要看得见）做，然后量出来证明做到了"。**

## 三处要收

### ① 统计页底部被导航栏切了

**现象**：最后一张卡（「今日概览」）的下边缘直接压在导航栏上。

**根因**：滚动容器 `.main--page` 的 `padding-bottom` 写死 12px，
而导航栏在三套主题下高度不一样（纸感 37、霓虹 50、系统感 54，各带不同外边距）。
写死的 12px 永远对不上任何一套。

**修法**：导航栏高度**实测注入** —— `App.tsx` 用 `ResizeObserver` 量出
`.nav` 的实际高度写进 CSS 变量 `--nav-h`，样式层用
`calc(var(--nav-h) + 24px)` 算底部留白。

不写死、也不靠眼睛估。切主题时导航栏高度变了，观察器自动更新。

**验收（量的）**：

| 项 | 值 |
|---|---|
| 导航栏实测高 | 37.33px（纸感），`--nav-h` 取 `max(56, 实测)` = 56px |
| 底部 padding-bottom | 80px |
| 最后一张卡下边缘 → 导航栏上边缘 | **80px**（要求 ≥80） |
| 滚到底时最后一张卡是否完整可见 | 是（`lastCardBottom=467 ≤ containerBottom=547`） |

### ② 音乐行歌名和歌手的接缝乱了

**现象**：长歌名截断后是 `夏日约定（Live版 · … - JINBAO` ——
省略号后面紧跟一个" - "，读起来像省略号里还藏了半句话。

**修法**：采纳肥鱼的倾向方案 —— **歌名左对齐、歌手右对齐，中间留白**。
两个元素彻底分开，歌手那块永远不会被歌名的省略号污染。分隔符" - "直接删掉。

**一个必须写的坑**：歌手那一块 `flex-shrink` 必须是 **0**。
第一版写的 `flex: 0 1 auto`，实测下来歌名很长时两者按各自内容宽度分摊缩量，
`JINBAO` 被压成 25px 还要再省略一次 —— 比原来的 bug 更糟。
宁可让歌名全截光，歌手也要完整。

**验收（量的）**：歌名 `[48,185]`、歌手 `[197,239]`，两块不重叠；
长歌名被截断（`titleTruncated=true`）而歌手完整（`artistTruncated=false`，宽 43px）。

### ③ 纸感下「＋ 主题」的虚线太淡

**现象**：纸感里几乎看不出框在哪。

**根因（比"太淡"更具体）**：三套主题各有一条结构覆盖规则把虚线盖掉了 ——
纸感是 `border: none`（直接把框抹了），霓虹是 `border: 1px solid var(--line)`
（把虚线样式盖回实线），系统感是 `border: none`。
只在 `app.css` 里改虚线颜色根本不生效，**必须在主题文件里重新声明**。

**修法**：新增主题变量 `--dashed-edge`，三套主题各给一档，
组件里只引用变量。脚本按 WCAG 对比度验收（要求 ≥3:1）：

| 主题 | 实测对比度 |
|---|---|
| 纸感 | **3.32:1** |
| 霓虹 | **4.18:1** |
| 系统感（浅色档） | **3.28:1** |

## 肥鱼自己加的两条建议：都做了

### 音乐行和上面之间加 1px 分隔线

**做了。** 现在音乐行上边有一条 `--line` 的 60% 细线，
**没有这条线，音乐行和岛底同色，看着像"上面那几行多长了两行字"**；
有了它才像一条独立的控制栏。

连带要改的地方：音乐行高度 34 → 42px，
所以岛的展开态高度 126 → 134px（`shared/island.ts` 的 `expandedHMusic` 和
`island-glass.css` 的 `--island-h-expanded-music` **两边都要改**，
主进程按它算窗口大小，改漏了岛会被截）。
量过：窗口高 148px = 134 + 底部余量 14，没被截。

### 纸感下主题横条的颜色冲突

**做了。** 用户选的主题色（亮蓝、亮绿）直接铺在暖白纸上，跟"暖白 + 砖红"打架。

改法：**墨色打底 + 30% 主题色**。主题色本身**不改**（那是用户选的），
上面那个色点也保留原色 —— 身份还在，但不跟整体抢。

实现上横条颜色不再由组件直接写 `background`，而是塞进 `--topic-color`，
主题层决定这条横条长什么样（跟主题变量 `--dashed-edge` 一个套路）。

测量脚本量四样东西：统计页底部留白、三套主题虚线框的对比度、
音乐行的左右分栏、岛窗口高度。**没有一条是"我试了没问题"。**

### 测量脚本踩的三个坑

1. **「＋ 主题」在计时页，不在统计页**。第一版去统计页找 `.topics__chip--add`，
   三个主题全 FAIL —— 不是样式没生效，是我找错地方了。
2. **1px 边框在 1.5 倍缩放下 `getComputedStyle` 返回 0.667px**。
   这是设备像素比换算，不是 bug。断言改成 `边框宽 × dpr ≈ 1`。
3. **alpha 不等于看得见**。第一版只断言 `alpha ≥ 0.5`，
   纸感那条 alpha 是 1.0 但对比度只有 2.08:1 —— 照样太淡。
   改成按 WCAG 算对比度才发现真问题。
