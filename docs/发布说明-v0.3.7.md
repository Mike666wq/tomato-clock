# 0.3.7

日期：2026-11-24

## 这次解决什么

**① 播放/暂停的图标终于是真的了**

以前那个按钮显示的方向是**猜**的 —— 读不到"现在在放什么歌"的时候，
我们不知道音乐是在放还是在停，只能挑一个显示。你截图里那个图标不对，
就是因为猜错了方向。

现在改成读**系统音频会话**：看那个播放器这一刻**有没有真的在出声**。

- 在出声 → 显示「暂停」图标（点了会停）；
- 静音了 → 显示「播放」图标（点了会放）；
- 还是读不到 → 显示两态图标，点了发切换命令（**不猜方向**）。

**② 上一首 / 下一首的图标画正了**

原来这两个的竖条位置画反了，渲染出来是镜像的。
标准形态现在是：上一首 `|◀◀`，下一首 `▶▶|`。
两态图标也跟「下一首」区分开了，一眼能分清。

**③ 顺手修了一个自己引入的毛病**

图标改成真状态之后，点一下播放/暂停，**岛会当场自己收起** ——
因为按钮上的图标节点被换掉，浏览器以为鼠标移走了。
现在图标节点固定，只换里面的形状，点了岛不会塌。

## 这轮量出来的东西（都是实测，不是推测）

| 事实 | 数值 |
|---|---|
| 读"在不在出声"的延迟（峰值） | 暂停 1.9 秒 / 播放 0.9 秒 |
| 读"会话是否 Active"的延迟 | 暂停 **23.5 秒** / 播放 1.1 秒 |
| 点真机按钮 → 状态真的反转 | 通过 |
| 图标形状（几何数据断言） | 通过 |

> 顺带说明：会话的 Active 状态**不能**当"在不在放"用 ——
> 暂停后它要 23.5 秒才变。真正实时的是**峰值**（这一刻有没有声音）。

## 已知限制

- **媒体键是全局的**：同时有别的播放器在放时，这一下可能打到别人身上。
  这是 Windows 的机制，不是这个应用的 bug。
- **歌名还是可能读不到**：Windows 上读"现在在放什么歌"只有 SMTC 一个官方接口，
  而 QQ 音乐这一版不再向系统报告会话（它的旧内核会报告）。
  读不到时那一块就是空的 —— **那不是坏了**，控制照常能用。
- 播放方向认的是**已知的播放器**（QQ 音乐等）；别的播放器读不到方向时，
  显示两态图标（不猜）。
