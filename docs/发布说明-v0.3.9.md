# 0.3.9

日期：2026-11-24

## 这次解决什么

**① 音量滑条一点就消失（真 bug，影响使用）**

按住滑条开始拖，**滑条会当场消失**，拖不动。

原因：岛本身是个"点一下就切换计时"的大按钮，它有个规则是
"滑条开着的时候，点岛上别处就收起滑条"。滑条只拦住了鼠标按下的那次事件，
**但"松开"那一下的点击事件照样传到了岛** —— 于是滑条刚被按住就被收走了。

现在滑条把这两次都拦住了。

**② 歌名又显示出来了**

QQ 音乐这一版不再向 Windows 报告"我在放什么歌"，所以上一版歌名那一块是空的。

现在多了一条路：**读音乐播放器主窗口的标题** —— 那个标题本来就是「歌名 - 歌手」，
切歌的时候立刻跟着变。

- 官方接口能读到歌名时，还是用官方的；
- 读不到时，才退到窗口标题这条路；
- 非 QQ 音乐的播放器读不到就还是空着（不显示假的）。

**③ 播放/暂停的图标终于是真的了**

以前那个按钮显示的方向是**猜**的 —— 读不到状态时，我们不知道音乐在放还是在停，
只能挑一个显示。你截图里那个图标不对，就是因为猜错了方向。

现在改成看那个播放器这一刻**有没有真的在出声**：

- 在出声 → 显示「暂停」图标（点了会停）；
- 静音了 → 显示「播放」图标（点了会放）；
- 还是读不到 → 显示两态图标，点了发切换命令（**不猜方向**）。

**④ 上一首 / 下一首的图标画正了**

原来这两个的竖条位置画反了，渲染出来是镜像的。
标准形态现在是：上一首 `|◀◀`，下一首 `▶▶|`。
两态图标也跟「下一首」区分开了，一眼能分清。

**⑤ 顺手修了一个自己引入的毛病**

图标改成真状态之后，点一下播放/暂停，**岛会当场自己收起** ——
因为按钮上的图标节点被换掉，浏览器以为鼠标移走了。
现在图标节点固定，只换里面的形状，点了岛不会塌。

## 这轮量出来的东西（都是实测，不是推测）

| 事实 | 数值 |
|---|---|
| 读"在不在出声"的延迟（峰值） | 暂停 1.9 秒 / 播放 0.9 秒 |
| 读"会话是否 Active"的延迟 | 暂停 **23.5 秒** / 播放 1.1 秒 |
| 歌名切歌后跟着变 | 通过 |
| 点真机按钮 → 状态真的反转 | 通过 |
| 图标形状（几何数据断言） | 通过 |

> 顺带说明：会话的 Active 状态**不能**当"在不在放"用 ——
> 暂停后它要 23.5 秒才变。真正实时的是**峰值**（这一刻有没有声音）。

## 已知限制

- **媒体键是全局的**：同时有别的播放器在放时，这一下可能打到别人身上。
  这是 Windows 的机制，不是这个应用的 bug。
- **歌名的兜底只认 QQ 音乐**（按窗口类名认主窗口）。
  别的播放器如果官方接口读不到，歌名还是空的 —— 那不是坏了。
- 播放方向认的是**已知的播放器**（QQ 音乐等）；别的播放器读不到方向时，
  显示两态图标（不猜）。
