## 二、CDP 验证：`scripts/cdp-check.mjs`

用法：

```powershell
node scripts\cdp-check.mjs "表达式1" "表达式2" ...
```

- 每个表达式都在**渲染页面的上下文**里求值（`Runtime.evaluate`，`awaitPromise: true`）
- 输出格式：`表达式` 换行 `=> 结果`；抛错会打印 `!! 错误信息`
- 返回值用 `JSON.stringify` 呈现，对象/数组能直接看

### 常用断言模板

```powershell
# 1) 通道是否通（preload 有没有挂上）
node scripts\cdp-check.mjs "typeof window.pomodoro"

# 2) 主进程当前的计时状态
node scripts\cdp-check.mjs "window.pomodoro.timer.getState()"

# 3) 界面当前显示的东西（比截图更精确）
node scripts\cdp-check.mjs "document.querySelector('.ring__time')?.textContent" "document.querySelector('.phase-label')?.textContent"

# 4) 发动作（等价于用户点按钮）
node scripts\cdp-check.mjs "window.pomodoro.timer.action('toggle')"

# 5) 等一会儿再读（观察倒计时）
node scripts\cdp-check.mjs "new Promise(r=>setTimeout(()=>r(window.pomodoro.timer.getState()),3000))"

# 6) 写 DOM（模拟用户在输入框里打字，React 受控组件必须走原生 setter）
node scripts\cdp-check.mjs "(()=>{const el=document.querySelector('.record-card__input');const s=Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype,'value').set;s.call(el,'写方案');el.dispatchEvent(new Event('input',{bubbles:true}));return 'FILLED'})()"

# 7) 触发回车提交
node scripts\cdp-check.mjs "document.querySelector('.record-card').dispatchEvent(new KeyboardEvent('keydown',{key:'Enter',bubbles:true}))"

# 8) 点某个按钮（按 class 选）
node scripts\cdp-check.mjs "document.querySelectorAll('.chip')[2].click()"
```

### 只在开发模式存在的两个后门

用来把长流程压缩成几秒，**打包产物里完全没有**（第 3 轮 grep 验证过）：

| 后门 | 作用 |
|---|---|
| `window.pomodoro.timer.devSeed(phase, elapsedSec)` | 把计时器摆到指定阶段与"已过秒数"，`elapsedSec` 大于 0 时会真的跑起来，用来快速触发阶段流转 |
| 环境变量 `POMODORO_PHASE` / `POMODORO_ELAPSED` | 启动时直接摆到指定状态，用来截指定状态的图 |

例：

```powershell
# 3 秒内走完一个专注段（1499 = 25:00 差 1 秒）
node scripts\cdp-check.mjs "window.pomodoro.timer.devSeed('focus',1499)" "new Promise(r=>setTimeout(()=>r(window.pomodoro.timer.getState()),2500))"
```

## 五、每轮要验的清单

按顺序过，缺一条不算完成：

1. **通道**：`typeof window.pomodoro` → `"object"`
2. **计时在走**：`getState()` 的 `remainingSec` 随时间递减
3. **窗口关了也在走**：关闭窗口（`taskkill /PID <pid>`，不要用 `/F`）→ 等 20 秒 → `getState()` 的 `remainingSec` 掉了约 20
4. **阶段流转**：连续 seed 4 次专注 → `focusRounds` 到 4 时阶段变 `long`
5. **落盘**：阶段结束后 `data.json` 多一条 `sessions`
6. **actualSec 口径**：`plannedSec`/`actualSec`/`pausedSec` 与墙钟跨度对得上（`actualSec + pausedSec ≈ 墙钟跨度`）
7. **重启恢复**：重启应用 → 底部状态行的"今日 N 个番茄"恢复
8. **打包产物干净**：`pnpm build` 后 grep 下面这些关键字，必须 **0 命中**：
   `POMODORO_SHOT`、`capturePage`、`devSeed`、`POMODORO_PHASE`、`POMODORO_ELAPSED`、`remote-debugging-port`、`timer:dev-seed`、`9222`

```powershell
pnpm build
foreach ($k in @('POMODORO_SHOT','capturePage','devSeed','POMODORO_PHASE','POMODORO_ELAPSED','remote-debugging-port','timer:dev-seed','9222')) {
  $n = (Select-String -Path out\main\index.js,out\preload\index.js,out\renderer\assets\*.js -SimpleMatch -Pattern $k | Measure-Object).Count
  "{0,-24} {1}" -f $k, $(if ($n -eq 0) { '未出现 ✅' } else { "出现 $n 次 ❌" })
}
```

## 六、踩过的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot read properties of undefined (reading 'requestSingleInstanceLock')` | 环境里预置了 `ELECTRON_RUN_AS_NODE=1`，Electron 退化成纯 Node | `scripts/dev.mjs` 已自动清理 |
| 截图只拍到桌面壁纸 | 窗口没在前台，`CopyFromScreen` 截到的是桌面 | 用 Electron 的 `capturePage()`，或 CDP |
| 截图内容被放大 1.5 倍并裁掉 | `PrintWindow` 按 DPI 放大输出，而位图按逻辑尺寸建 | 同上，别用 `PrintWindow` |
| 模拟点击没反应 | 点击落到桌面上了 | 改用 CDP 直接驱动渲染层 |
| `No handler registered for 'timer:dev-seed'` | 改主进程时把 DEV 块里的 handler 删掉了 | 注意 DEV 块与正式逻辑的对应关系 |
| 提示条不显示 | 主进程在渲染层挂载前推送，订阅还没建立，消息丢了 | 改成拉取式：渲染层挂载后 `notice.take()` |
| `pnpm add` 时 TypeScript 7 的原生二进制反复超时 | TS 7 是原生实现 | 钉 `typescript@^5.9` |
| `pnpm install` 一直报 `ERR_PNPM_EPERM`（导入 electron-winstaller） | symlink 布局下 tmp 目录重命名失败，疑似长路径 + 中文目录名 + 杀软扫描叠加；干净目录能装上 | 改用 hoisted 扁平布局：`.npmrc` 里 `node-linker=hoisted` |
| `pnpm run xxx` 全都失败，堆栈里是 `runDepsStatusCheck` | pnpm 跑脚本前会先跑一次 install，而 install 因为"有构建脚本被忽略"返回非 0 | `pnpm-workspace.yaml` 里用 `allowBuilds` 明确声明：`electron: true`、`electron-winstaller: false` |
| 打包最后一步 `Offset is outside the bounds of the DataView` | 自己手写的 ICO 目录项尺寸和里面的 PNG 不一致，resedit 解析炸了 | ICO 每个尺寸都要写真实的宽高，256 要写成 0；用 `scripts/gen-assets.ps1` 生成 |
| `pnpm dev` 报 `Error: Electron uninstall` | `node_modules/electron/dist` 和 `path.txt` 被清掉了（electron 二进制没了，electron-vite 找不到可执行文件） | `node node_modules\electron\install.js` 从本地缓存恢复（`%LOCALAPPDATA%\electron\Cache` 里有 zip，秒级完成，不用重新下 238MB） |
| **Windows 上透明窗口 `resizable:false` 会把程序化 `setSize` 一起禁掉** | 展开之后再也收不回去（`setSize` 被系统吞掉，窗口尺寸永远停在展开态） | 改成 `resizable:true`，另外用主进程 `win.on('will-resize', e => e.preventDefault())` 拦住用户手动拖边缘 |
| 亚克力材质铺满整个窗口矩形，CSS 圆角裁不住 | `backgroundMaterial:'acrylic'` 的材质是 DWM 画的，铺满窗口，不受页面形状影响 | **已弃用真亚克力**，改走伪毛玻璃（透明窗口 + CSS 圆角 + 噪点/高光/内阴影四层） |
| `win.setShape()` 救不了形状 | 它只裁**内容**，材质照旧铺满矩形（实测：shape 裁成 60×16，材质仍铺满整窗） | 同上，不用 setShape |
| `transparent:false` + `backgroundMaterial:'acrylic'` 糊不出来 | 不透明窗口的底色把材质盖住了，只剩一块灰底 | 真亚克力这条路整体放弃 |

## 七、已知保留项（别再讨论一遍）

| 项 | 结论 |
|---|---|
| `ELECTRON_RENDERER_URL` 出现在打包产物里 | **保留**。这是 electron-vite 官方机制：开发时用它告诉主进程去哪个地址加载渲染层。代码路径已被 `import.meta.env.DEV` 包住，产物里那段不会执行，不构成后门。 |
| `electron-winstaller` 的构建脚本被忽略 | **保留**。它只服务于 Squirrel 打包器（本项目用 NSIS + 免安装 zip），用不到。 |

**灵动岛截图**（要能看出它悬在屏幕顶端）：

```powershell
$env:POMODORO_ISLAND_SHOT='C:\...\docs\shots\r6-灵动岛.png'
```

透明窗口没法用 `capturePage` 表现"悬浮感"，所以桌面那张是 `desktopCapturer` 抓屏后裁出来的。

**贴顶居中的算法**（别自己换算物理像素）：

```
x = workArea.x + (workArea.width - 窗口宽) / 2      // workArea 已排除左侧任务栏
y = workArea.y                                        // 本机 = 0
```

本机实测：主屏工作区 `x=48, y=0, 1659×1067`（任务栏在左），窗口 `screenX=783, screenY=0`，即正中贴顶。

### 真亚克力为什么不用（做过实验，别再重测）

| 实验 | 结果 |
|---|---|
| `transparent:true` + `backgroundMaterial:'acrylic'` | 真模糊出来（DWM 把桌面糊给你）✓ |
| `transparent:false` + acrylic | 只有一块灰底，糊不出来 |
| 叠 `win.setShape([60×16])` | 材质仍铺满整个窗口矩形 —— **只裁内容不裁材质**，救不了形状 |
| 页面画小圆、窗口留大片透明 | 整窗都是糊的 —— 材质不受页面形状约束 |
| 圆角交给 DWM（`roundedCorners:true`） | 半径固定约 8px、四角同时圆、不可控；而且展开收起的尺寸动画会一跳一跳 |

结论：**形状要靠 CSS 圆角，模糊就只能是伪的**。伪毛玻璃四层（缺一层就不像玻璃）：
半透明底 `rgba(16,18,22,0.72)` + `feTurbulence` 噪点（opacity 0.035，overlay）+ 顶部 1px 高光与下沿暗边 + 内阴影。

### 验收：深色 / 浅色壁纸各一张

把岛的透明截图合成到两种背景上看边界是否清楚：

```powershell
python .tmp\composite-island.py
# 产出 docs\shots\r7-胶囊-深色壁纸.png / r7-胶囊-浅色壁纸.png
```

浅色壁纸上如果胶囊糊成一片灰、看不出边界，就是不合格（要回去调底色不透明度）。

> 注意：**别拿 `desktopCapturer` 的合成图当最终判断**。透明窗口在这种合成里容易出"胶囊外面多一圈浅色框"的边区，其实是投影被看成了框。

> ```powershell

> $g = [System.Drawing.Graphics]::FromImage($bmp); $g.CopyFromScreen(0,0,0,0,$bmp.Size)
> $bmp.Save('.tmp\gdi.png',[System.Drawing.Imaging.ImageFormat]::Png)

> 实测结论：`transparent:true` / `backgroundColor:'#00000000'` / `backgroundMaterial:'none'` 三项都正常，**GDI 抓图里胶囊周围没有多余边框**。

### 数据与迁移

- 存储版本从 **1 升到 2**（方案文档里写的是 2→3，实际仓库当时是 1，以代码为准）。
- 迁移：把老的 `focusMin / shortBreakMin / longBreakMin / roundsBeforeLong` 打包成一个名叫**「我的设置」**的模板并设为当前模板，老用户打开还是原来的时长；顺带补上四个内置模板（经典/深度/冲刺/考试）。

```powershell
$d = Get-Content "$env:APPDATA\pomodoro\data.json" -Raw | ConvertFrom-Json
```

### 切换规则（最容易写错的一条）

**计时进行中切模板：当前段不变，下一段生效。**
**下一段用的是"下一段开始时"的当前模板**——不是这一段开始时的值（用户很可能在休息里切模板）。

实测（CDP，`$env:CDP_TARGET='island'`）：

| 场景 | 期望 | 实测 |
|---|---|---|
| 计时中切模板 | 当前段 `totalSec` 不变 | 3000s 不动 ✓ |
| 空转（这一段还没跑）时切模板 | 立刻生效 | 1500 → 900 ✓ |
| 切到「冲刺」后跳过 | 下一段是冲刺的时长 | 短休/长休 600s（冲刺 10 分钟）✓ |
| **休息段里切到「深度」，再跳过** | **下一段专注 3000s（深度 50 分钟）** | **3000s ✓**（这条就是方案里点名的那条） |

## 十一、主题系统（v0.3-b）

### 数据与迁移

- 存储版本 **2 → 3**：老记录补 `topicNameSnapshot = ''`（`topicId` 为空 = 未分类），设置里补 `topics: []` / `activeTopicId: null`。
- **迁移幂等**：启动两次，`schemaVersion` 是 3，主题数不变，历史记录不重复处理。
- 首次启动**不预置任何主题**（用户自己建第一个）。

### 主题规则（实测）

| 场景 | 期望 | 实测 |
|---|---|---|
| 跑完一段专注 | 记录带上 `topicId` + `topicNameSnapshot` | `topicId=t1, topicNameSnapshot=写代码` ✓ |
| 休息段 | 不挂主题 | 休息记录 `topicId` 为空 ✓ |
| 运行中切主题 | 当前段不变，选中变成新的 | `topicId` 保持 t1、`activeTopicId` 变 t2 ✓ |
| 切主题后跳过 | 下一段挂新主题 | `topicId=t2` ✓ |
| 统计 | 占比 / 回合数 / 平均时长 / **打断率** | 未分类 89%（6 个番茄·126 分·平均 21 分·打断率 17%）、写代码 11%（打断率 0%）✓ |

打断率 = 该主题的完成回合里被打断的比例（`interrupt !== 'none'` 计数 / 总回合数）。

## 十二、灵动岛展开态（v0.2-c 重做后定版）

### 两层结构（不平铺）

```
第一层：时间 + 任务名 + 三个图标   |   第二行：两个"当前值胶囊"
第二层：点某个胶囊 → 第二行换成那一项的候选项（一次只展开一行）
```

- 第二行默认是两个当前值胶囊：`经典 · 25/5` 和 `写代码`（主题）。
- 点模板胶囊 → 第二行变成全部模板（经典 25/5 / 深度 50/10 / 冲刺 15/3 …）；点主题胶囊 → 变成全部主题。
- **一次只展开一行**，加多少模板主题都不会撑爆。
- Esc 逐层收回：先收回第二层，再收起整个岛。

### 底色到底透不透（别靠眼睛，用 A/B 对比测）

同一块屏幕，先抓"有岛"的图，再把岛隐藏抓一张"没岛"的图，同一像素相减：

```
胶囊值 = a × 底色 + (1-a) × 壁纸值   →  a = (壁纸值 - 胶囊值) / (壁纸值 - 底色)
```

| 底色 | 实测有效不透明度 | 胶囊内亮度 p10/p50/p90 |
|---|---|---|
| rgba(44,44,44,0.9) | **0.895**（2501 个样本，中位数） | 47 / 55 / 66 |
| rgba(44,44,44,0.95) | 0.944 | 49 / 55 / 56 |

结论：**CSS 的不透明度是如实生效的**，0.9 时壁纸的泡沫/水反差（240 vs 16）会透出可见纹理；
0.95 之后纹理基本消失，胶囊内亮度被压到 33–44，稳定在近黑。

**另外**：暂停态**不要**给整个胶囊加 `opacity`——底色本来就靠不透明度压深，再乘一次，壁纸纹理会重新透出来。暂停只用圆点和数字转灰表示。

### 系统原生 tooltip 要去掉

深色界面里冒一个白底黑字的系统提示框，刺眼得像没做完。**所有 `title` 属性去掉**；
需要说明就用自绘的暗色小提示（`data-tip` + CSS `::after`），或者干脆把信息直接显示出来
（模板胶囊写成 `经典 25/5`，信息就在脸上）。

### 任务名就地编辑

灵动岛上点任务名 → 变成输入框 → 回车保存。任务名存进计时器（`segmentTask`），
这段跑完时写进记录。

> **踩过的坑**：`handlePhaseComplete` 里如果先 `await` 读设置、再读计时状态，
> 等 await 回来时 `advance()` 已经把任务名清空了（下一段的任务名），记录里就是空的。
> **完成信息必须自己带上任务名和主题**（`PhaseCompleteInfo.task / topicId`），
> 不能事后去读状态。主题当时是"碰巧"对的。

### 三处视觉细节（v0.2-c 收尾）

|---|---|---|
| 进度条从圆角里戳出来 | 条贴着底边画（内缩 12px、离底 6px），而胶囊下沿是 17px 圆角 | 内缩改 18px、离底改 8px，圆角弧线够不着它 |

## 十三、SMTC 探针结论（v0.4 的前置）

脚本：`scripts/smtc-probe.ps1`（一次性探针，**没进产品代码**）。
运行方式：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\smtc-probe.ps1`

**结论：纯 PowerShell 只能枚举，拿不到歌名、也发不出控制命令。**

| 能力 | 结果 |
|---|---|
| 加载 `GlobalSystemMediaTransportControlsSessionManager` | ✅ |
| 加载 `SystemMediaTransportControlsSession` / `MediaPlaybackProperties` | ❌ 加载不出来（WinRT 投影不出这两个类） |
| 枚举会话 | ✅ **本机实测拿到 1 个会话：`Tencent.QQMusic`** |
| 拿标题 / 艺术家 | ❌ `GetMediaPropertiesAsync` 不在投影里 |
| 发播放 / 暂停 / 下一首 | ❌ `TryPause` / `TryPlay` / `TrySkipNext` 不在投影里 |

**卡点**：PowerShell 5.1 的 WinRT 投影只投出了会话管理器，投不出 Session 和 MediaPlaybackProperties，
拿到的会话对象是个没有成员的空壳。

**绕过去的代价**：
- C# 助手路线（`csc` + 引用 `Windows.Media.winmd` + 参考程序集）能把类型投影出来，
  但离线环境下卡在经典问题上：`Windows, Version=255.255.255.255` 这个 WinRT 程序集标识解析不了。
- 媒体键路线（`SendInput` 发 `VK_MEDIA_PLAY_PAUSE` / `VK_MEDIA_NEXT_TRACK`）不需要 WinRT，能控制，
  但**拿不到歌名**。（没实测：会打断你正在听的音乐。）

**成本参考**（本机实测）：会话枚举 **0.2 ms/轮**（进程内）；冷启一个 PowerShell 子进程 **223 ms**；
整个探针 **353 ms**。

**建议**：v0.4 要么做"只能控制、不能显示歌名"的极简版（媒体键路线），
要么先把 C# 助手的编译环境配通再动；不能靠纯 PowerShell。

## 十四、主界面布局（v0.2.1 修，用户截图暴露的 P0）

**现象**：用户把窗口缩到 500×589，模板条和主题行压在一起，底部导航被切掉一半，
"今日 X 个番茄"那行状态被挤没了，圆环还是写死的 320，把下面全顶出去了。

**根因**：布局是按固定像素堆叠的，没有弹性也没有滚动。

**修法**：

1. 纵向 flex：顶部（标题栏、阶段标签）固定 → 中部圆环区 `flex:1` → 底部（按钮 + 模板条 + 主题行 + 状态行）固定 → 导航栏永远贴底。
2. **圆环尺寸按可用空间算**，不写死：`min(420, 可用宽 - 96, 可用高 × 0.78)`，最小 200。
   数字跟着环缩放：`font-size: calc(var(--ring-size) * 0.2875)`。
3. 中部 `overflow-y: auto`，装不下就滚，不压叠。
4. 窗口最小尺寸 `420 × 560`；启动时记住的尺寸小于它就**强行修正**（旧版本存进去的脏尺寸会一直复现）。

**踩到的坑**：`.main` 是 `align-items: center`，弹性子项默认按内容宽收缩 →
圆环区被压成 200 宽（= 环的宽），可用宽算出来一直是负数，环永远是最小值。
**给这一格补 `width: 100%`** 才是对的。

**验收尺寸**（别只在默认尺寸下截）：500×589（用户那张）和最小 420×560 各截一张，
实测：环 215、导航栏 top=552（= 窗口高 590 - 导航 38）、状态行在。

## 十五、v0.2.2：音乐控制接进灵动岛 + 三处 UI

### 15.1 音乐控制（SMTC 子进程）

**结构**：主进程（Node，没有 WinRT 投影）拉一个 C# 子进程
`tools/smtc/publish/smtc.exe`（打包后落在 `<resourcesPath>\resources\smtc\smtc.exe`），
它每秒往 stdout 写一行 JSON：

```json
{"kind":"state","source":"Tencent.QQMusic","title":"…","artist":"…","playing":true}
{"kind":"ack","command":"play","ok":true}
```

主进程按 `kind` 分流：`state` 广播给渲染层，`ack` 是命令回执（`ok` 时乐观更新播放状态）。

**关键点**：

- **默认关**：`settings.showMusicControl` 默认 `false`，设置页有开关，切换即刻生效（不需要重启）。
- **静默降级是常态**：找不到 exe / 没开音乐软件 / 子进程崩了 → 状态为 `null`，
  灵动岛那一行**整个消失**，不留空行、不报错条。子进程崩了最多安静重试 3 次。
- **窗口高度跟着那一行走**：出现/消失时展开态高度在 92 ↔ 118 之间变，
  主进程按 `island:set-mode` 传的第二个参数（有没有音乐行）算窗口高度。
- **收起态不显示**这一行（收起态只有 172 宽）。

**验证**：

```powershell
# 1) 工具本身
node scripts\prepare-smtc.mjs                       # 发布到 tools/smtc/publish
tools\smtc\publish\smtc.exe current                 # 一次性读当前会话
tools\smtc\publish\smtc.exe watch                    # 常驻，每秒一行

# 2) 跑起来之后
$env:CDP_PORT='9222'; $env:CDP_TARGET='island'
node scripts\cdp-check.mjs "window.island.media.getState()"
node scripts\cdp-check.mjs "window.island.media.command('pause'); 'sent'"
node scripts\cdp-check.mjs "new Promise(r=>setTimeout(()=>r(window.island.media.getState()),1200))"
# → playing 变 false；再 command('play') 变回 true
```

**踩到的坑**：

- 打包版启动时如果环境里还留着 `ELECTRON_RUN_AS_NODE=1`，exe 会退化成纯 Node，
  报 `bad option: --remote-debugging-port=9223` 直接退出。启动前先 `Remove-Item Env:ELECTRON_RUN_AS_NODE`。
- `extraResources` 的 `from` 目录不存在时 electron-builder 会报错，
  所以 `scripts/prepare-smtc.mjs` 在发布失败时也要留一个空目录。

## 十六、v0.2.3：用户真用出来的三个 bug

用户装上 0.2.2 跑了一段，报"主题切不了、灵动岛输入有问题"。查下来是三个独立的 bug。

### 16.1 主题"点了没反应"（显示错，不是存储错）

高亮用的是 `state.topicId`（**这一段正在跑的**主题），而切换写的是
`settings.activeTopicId`（**用户选中的**主题）。按设计切主题只影响下一段，
所以 `state.topicId` 不会变 → 存进去了，界面纹丝不动。

修：高亮一律跟 `settings.activeTopicId`；两者不一致时，给"本段实际在用"的那个
加一个 9px 的「本段」小标记。涉及 `Island.tsx`（当前值胶囊 + 选项行）和 `Timer.tsx`。

### 16.2 灵动岛输入框一打字就消失

`onLeave` 里没有 `editingTask` 判断，鼠标离开 400ms 就 `setMode(false)`，
窗口缩回收起态，输入框跟着没了。另外浮层不主动要焦点，字符会打到主窗口去。

修三处：

1. `onLeave` / Esc 在编辑态直接 return（Esc 改为"取消编辑"，不收起岛）；
2. 点空白处 = 提交并结束编辑，不再顺手切换开始/暂停；
3. 进编辑态时走 `island:focus` IPC → 主进程 `win.focus()` + `webContents.focus()`。

**验收**：`document.activeElement` 是输入框、`document.hasFocus()` 为真；
派发 `mouseout` 后等 900ms（> 400ms 收起延时）岛仍是 `island--expanded`。

### 16.3 启动后第一个专注段不挂主题（真丢数据）

`Timer` 构造函数没初始化 `segmentTopicId`，而它只在 `updateSettings` / `reset` /
`advance` 里被赋值。于是**每次启动应用后的第一个专注段永远记成未分类**——
用户在设置里明明选着主题，跑完一看记录是未分类。

修：构造函数里补 `this.segmentTopicId = cfg.topicId`。

**验收**：全新启动 → 选中某主题 → 直接开始 → `getState().topicId` 必须等于该主题。

### 16.4 CI 打包失败的真凶（`--publish never`）

CI 在 `pnpm dist` 最后一步 exit 1，错误是：

```
⨯ GitHub Personal Access Token is not set, neither programmatically, nor using env "GH_TOKEN"
```

**包其实已经打完了**（NSIS 都跑到 99.7%）。原因是 `CI=true` 会让 electron-builder
进入"可发布"模式，去找 `GH_TOKEN`，找不到就退出 1。

本地复现必须把 `CI=true` 设上，否则永远看不到：

```powershell
$env:CI='true'; $env:GITHUB_REF='refs/heads/master'
$env:GITHUB_REPOSITORY='owner/repo'; pnpm dist   # → exit 1
```

修法：`dist` 脚本加 `--publish never`（发布统一交给 `action-gh-release`）。
加了之后同样命令 exit 0，三个包齐全。**这条以后别再动回去。**

> 顺带一个反直觉结论：electron 45 的包里**没有 postinstall**（只有一个
> `install-electron` bin），所以 `pnpm-workspace.yaml` 里的 `allowBuilds: electron`
> 实际不触发任何脚本；`node_modules/electron/dist` 缺失也不影响
> `pnpm dist`——electron-builder 自己下载 electron 包。

### 16.5 ⚠️ 不要在 CI 里用 `upload-artifact`（免费额度 500 MB，我们一次 392 MB）

**这一条比 16.4 更危险，因为它不是"占额度"，而是会把正式包一起带走。**

- 免费账户 Actions **存储总额 500 MB**，我们的三个包一次 **392 MB**。
- 推 master 和打 tag 会各跑一次 job，两次都传就是 **784 MB**，必然撞上限。
- 上传失败的后果不是"少一个 Artifact"：**这一步一失败，整个 job 就失败**；
  而 `建 Release` 那步要求 `success()`，于是 **Release 也建不出来**。
  用户那边表现就是"打了个 tag，什么都没出来"。

**现在的流程（v0.2.3 起）彻底不碰 Actions 存储：**

| 触发 | 产物去哪 | 占额度 |
|---|---|---|
| 打 `v*` 标签 | 正式 Release（带版本号，稳定） | 否（Release 附件不算 Actions 存储） |
| 推 master | `latest-build` **滚动预发布**，每次覆盖 | 否 |
| 任何时候 | ~~Artifacts~~ | **已移除** |

两者都挂三个包（安装版 / 免安装单文件 / 免安装 zip）。用户下载入口是 Release 页，
不需要登录 GitHub；Artifacts 那个入口本来还要登录才下得动。

**以后谁想把 Artifacts 加回来，先读这一节。** 如果确实需要（例如要保留每次构建的
历史产物做对比），必须同时做到：`retention-days` 压到 1–3 天、只在非 tag 的推送上传、
并且 `continue-on-error: true`，别让它有能力拖垮 Release。

**另一个坑：`latest-build` 是固定 tag 名。** master 每推一次都往同一个 Release 上
覆盖附件，**连着推两次 master 会两个 job 同时写同一个 Release**，附件的最终状态不确定。
改完东西攒成一次推，或者等上一次跑完再推。

### 16.6 Release 附件的中文名会被吞

上传到 Release 的附件，GitHub 会把中文吃掉、把空格变成点。原本叫：

```
番茄钟 0.2.3.exe
番茄钟 Setup 0.2.3.exe
番茄钟-0.2.3-免安装.zip
```

挂到 Release 上变成：

```
0.2.3.exe
Setup.0.2.3.exe
-0.2.3-.zip
```

用户下载下来分不清哪个是安装版。**修法**：上传前把三个包**复制**成 ASCII 名再传，
本地构建产物仍然保留中文名（本地不需要这套规则）。

```
tomato-clock-<ver>-setup.exe           安装版
tomato-clock-<ver>-portable-single.exe 免安装单文件
tomato-clock-<ver>-portable.zip        免安装 zip
```

### 16.7 核对"远程某个 ref 上有没有这段代码"的正确做法

**别信 `raw.githubusercontent.com`，也别信本地的 `origin/master`。**

踩到的实例（我自己踩的）：用 `https://raw.githubusercontent.com/<owner>/<repo>/master/<path>`
核对 `master` 上有没有"复制成 ASCII 文件名"那一步，读到的是一份**没有那一步的旧内容**，
于是得出"tag 有、master 没有、分支和标签分叉了"的错误结论。加了 `?cb=<随机数>`
也没用——那是 CDN 缓存，查询串破不掉。

真实情况是：`master` 和 `v0.2.3` **是同一个提交**，那一步在 master 上。用下面的办法
几分钟就能确认，也不用担心缓存：

```powershell
# 1) 拿远程真实的 sha（这一步才代表"现在远程是什么"）
git ls-remote origin refs/heads/master refs/tags/v0.2.3

# 2) 取下来（fetch 是只读的，不会推东西）
git fetch origin master --tags --force

# 3) 看内容。annotated tag 要解引用，否则拿到的是 tag 对象不是提交
git rev-parse origin/master
git rev-parse 'v0.2.3^{commit}'

# 4) 直接读那个 sha 上的文件，别读工作区、也别读 origin/master 的旧快照
git show <sha>:.github/workflows/build.yml | Select-String -Pattern 'ASCII|Copy-Item'
```

两个容易骗人的地方：

- **本地 `origin/master` 可能是上次 fetch 的快照**，`git show origin/master:<path>` 会
  **安静地**给你一份旧内容，不报错、不警告，看起来完全正常。
- **annotated tag** 的 sha 不等于提交 sha。`git rev-parse v0.2.3` 给的是 tag 对象，
  要 `v0.2.3^{commit}` 才是它指向的提交；两者比不相等不代表"分叉"。

**workflow 本身是跟着 ref 走的**：每个分支 / 标签各有一份 `.github/workflows/build.yml`，
tag 那份是打 tag 那一刻的快照。所以核对的单位永远是"某个 sha"，不是"远程大概是什么样"。

## 十七、本地只做开发，包一律在线上打（2026-11-22 起）

**约定**：本机不保留构建产物，不跑 `pnpm dist` 出包。要包就推 master（`latest-build`

|---|---|---|
| `node_modules/` | ~1.0 GB | `pnpm dev` 要用 |

## 十八、单元测试（v0.4 起，vitest）

```powershell
pnpm test          # 跑一遍
pnpm test:watch    # 盯着改
```

**测试文件**：`src/main/timer.test.ts`（状态机）、`src/main/stats.test.ts`（统计口径）。
测试名带规格编号（`it('C3 跳过之后不自动开始', ...)`），对着
《v0.4-逻辑规格与测试清单》能一条条对上。

### 18.1 时间怎么控制

`Timer` 有 `now()` 注入点（`new Timer(cfg, { now })`，默认 `Date.now`），
测试里传自己的假时钟：

```ts
let clock = 0
const timer = new Timer(cfg, { now: () => clock })
function advance(ms: number) {
  clock += ms               // 注入的时钟往前推
  vi.advanceTimersByTime(ms) // 让 200ms 的 ticker 触发
}
```

两个一起推：只推 `vi.advanceTimersByTime` 的话，`now()` 不动，倒计时不会走。

### 18.2 vitest 必须装 v5，不能装 v3

项目用的是 **vite 8**。vitest 3 的 peer 是 `vite ^5||^6||^7`，装它会被 pnpm
另外拉一份 vite 7 → **两份 vite → 两份 esbuild → 重新导入 esbuild 时撞上
这台机器的 `ERR_PNPM_EPERM`**（`.npmrc` 里记过这个老毛病：Windows 上
tmp 目录 rename 会失败）。

vitest 5 的 peer 是 `vite ^6.4.0 || ^7.0.0 || ^8.0.0`，直接复用现有的 vite 8，
不装第二个 esbuild，4 秒装完：

```powershell
pnpm add -D vitest@^5
```

### 18.3 时长单位是分钟，最小 1 分钟

`phaseSec()` 里是 `Math.max(1, 分钟) * 60`，所以**最短的一段是 60 秒**，
写测试时别想当然写 `shortMin: 10`（那是 10 秒）——那样会被兜底成 60 秒，
阶段流转的断言全错。要区分长短休就让 `longMin` 真的比 `shortMin` 大。

### 18.4 `Timer` 不碰文件

落盘（E 组）全在主进程：`Timer` 只提供 `getSnapshot()` / `restore()`，
IO 由主进程做。这样 `Timer` 仍是纯逻辑类，E 组也能用假时钟测。

## 十九、崩溃恢复（规格 E 组）的真机验证

快照文件：`%APPDATA%\pomodoro\running.json`（和 `data.json` 分开）。
**总纲 E0：应用退出 = 暂停**，所以恢复出来永远是暂停态 + 退出那一刻的剩余。

### 19.1 正常退出 → 重开恢复（E1）

```powershell
# 开发期跑起来
pnpm dev
$env:CDP_PORT='9222'; $env:CDP_TARGET='main'
node scripts\cdp-check.mjs "window.pomodoro.timer.action('start'); 'go'"
Start-Sleep -Seconds 10
node scripts\cdp-check.mjs "window.pomodoro.timer.getState().then(s=>JSON.stringify({rem:s.remainingSec}))"

# 正常退出（app.quit，会走 before-quit 落盘）
node scripts\cdp-check.mjs "window.pomodoro.window.devQuit(); 'quitting'"

# 看快照：running 必须是 false，remainingSec = 退出那一刻的剩余
Get-Content "$env:APPDATA\pomodoro\running.json" -Raw
```

再 `pnpm dev` 起一次，验恢复：

```powershell
node scripts\cdp-check.mjs "window.pomodoro.timer.getState().then(s=>JSON.stringify({rem:s.remainingSec,running:s.running,total:s.totalSec}))"
# → running 必须是 false，rem 必须等于退出那一刻的值
```

> `window.pomodoro.window.devQuit()` 是**开发期专用**的 IPC（跟 `devSeed` 同一性质）：
> 托盘里的"退出"没法用脚本点，只能加个口子。打包产物里 grep `devQuit` 是 0 命中。

### 19.2 崩溃（kill 进程）→ 重开恢复（E2）

```powershell

Start-Sleep -Seconds 8
Get-Process electron | Stop-Process -Force     # 模拟崩溃/断电

# → 暂停态，rem = 最后落盘那一刻的值，**不是**现在的值（不推算流逝的时间）
```

### 19.3 快照损坏 → 不崩（E6）


## 二十、主题与真机截图（v0.5）

### 20.1 用户自己的正式版开着时，怎么跑开发版

正式版和开发版共用一个 `userData`（`%APPDATA%\pomodoro`），
`requestSingleInstanceLock` 会让**开发版一起来就退出**（退出码 0，不报错，很难查）。

解法：给开发版单独一个 userData 目录，锁就分开了：

```powershell
New-Item -ItemType Directory -Force .tmp\devprofile | Out-Null
Copy-Item "$env:APPDATA\pomodoro\data.json" .tmp\devprofile\data.json -Force   # 想看同样的数据就拷过去
pnpm exec electron-vite dev -- --user-data-dir=C:\Users\bbben\Desktop\番茄钟\.tmp\devprofile
```

`electron-vite dev --` 后面的参数会转给 electron ✓。
副作用：全局快捷键被正式版占着，开发版会提示"快捷键注册失败"——正常，不影响界面。

### 20.2 拍最小窗口 420×560

CDP 截图加一个视口尺寸参数：

```powershell
$env:CDP_PORT='9222'; $env:CDP_TARGET='main'
$env:CDP_EMULATE='420x560'; $env:CDP_OUT='docs\shots\xxx.png'
node scripts\cdp-shot.mjs
```

布局会跟着视口变，截出来的就是最小窗口的样子（比真的拖窗口小一圈，省事）。

### 20.3 "放在桌面上跳不跳"：合成，不动用户的桌面

GDI 抓的是屏幕最终合成结果，前面盖着别的窗口就拍不到界面；
而为了桌面干净去最小化用户的窗口（Win+D / 枚举窗口）副作用太大——**还会误伤**
（按类名枚举会连 Electron 窗口一起最小化，DS Bot 也可能被收起来）。

所以用合成：**界面像素是真的**（CDP 抓的窗口自己），**壁纸是真的**（用户当前的壁纸），
缺的只是窗口阴影那一层。

```powershell
$wp = (Get-ItemProperty 'HKCU:\Control Panel\Desktop').WallPaper
python scripts\make-wallpaper-context.py "docs\shots\纸感-主界面-真机.png" $wp "docs\shots\纸感-深色壁纸.png" 133 80
```

参数：界面图、壁纸图、输出、窗口 x（逻辑像素）、窗口 y。
坐标用**逻辑像素**，脚本自己乘 1.5（这台机器的缩放比）。

> 真要改壁纸用 `scripts\wallpaper.ps1`（改完记得 `-Restore`，它会把原路径记在
> `.tmp\wallpaper-backup.txt`）。这次没改，用的是合成。

### 20.4 进度弧和数字必须一致

稿子里"25:00 配 70% 的弧"是假数据。真实现里 0% 就是空弧。

验法（起一次计时，再读 DOM 和状态对账）：

```powershell
$env:CDP_EVAL=@'
(async () => {
  document.querySelector('.btn--primary').click()
  await new Promise(r => setTimeout(r, 6000))
  const st = await window.pomodoro.timer.getState()
  const el = document.querySelector('.ring__progress')
  const px = document.querySelector('.ring').getBoundingClientRect().width
  const stroke = parseFloat(getComputedStyle(document.documentElement).getPropertyValue('--ring-stroke'))
  const r = (px - stroke) / 2 - 4
  const circ = 2 * Math.PI * r
  const expected = 1 - st.remainingSec / st.totalSec
  const actual = 1 - parseFloat(el.getAttribute('stroke-dashoffset')) / circ
  document.querySelector('.btn--primary').click()   // 停掉，别把用户的计时开着
  return JSON.stringify({ expected, actual, diff: Math.abs(expected - actual) })
})()
'@
node scripts\cdp-shot.mjs
```

`diff` 的量级应该在 **1 秒以内**（0.0007 左右）——界面是每秒跳一次的，
弧比数字慢一拍是正常的；差得更多就说明弧和数字不是一回事。

### 20.5 窗口底色别闪黑

纸感是浅底。启动时如果窗口底色还是深色，会先闪一下黑。

验法：看主进程日志没有异常，再看 `windowBgOf()` 取的是不是 `UI_THEME_BG[主题][深浅]`。
换主题后窗口底色要立刻跟着换（`settings:save` 里那行 `setBackgroundColor`）。

## 二十一、两条铁律（2026-11-23 起，每轮都适用）

这两条是肥鱼在 v0.6.3 那轮定下来的，写在这儿就是**规矩，不是每次临时想起**。

### 21.1 完整流程：单测 → 端到端 → 打包 → 打包版验包

**每一轮改动都要走完这四步，缺一步不算完成。**

| 步骤 | 命令 | 通过标准 |
|---|---|---|
| 1. 单测 | `pnpm test` | 全绿 |
| 2. 端到端（开发版） | `node scripts\e2e-journey.mjs` | 全部 PASS |
| 3. 打包 | `pnpm build` + 搜开发期入口 | 一个都搜不到 |
| 4. **打包版验包** | 见 21.3 | 全部 PASS |

**为什么第 4 步不能省**：用户只装包，不装开发版。
开发版和打包版差**一个 asar、差 `NODE_ENV`、差一整套环境变量**。
前面已经栽过两次：

- 一次是产物里留着开发期的注入口（`POMODORO_USER_DATA` / `media:devFake` / `clock:dev-set`）。
- 一次是空 Release（附件对不上，Release 建出来是空的）。

**"开发版过了"不等于"包能用"。** 第 4 步是唯一的证据。

### 21.2 像素问题不许目测

> **判断像素对齐必须用 `mock-measure` 或 DOM 边界量，不许看截图说"歪了"。**

这条是肥鱼自己栽过之后立的：他从缩略图判断"11/22 那根柱子明显偏左"，
量下来两处本来就是同一个算法、柱子是对齐的。
**缩略图缩放后差两三个像素根本看不出来**，却据此断言是 bug。

同一条道理还有两个变体，本轮都踩了：

- **alpha 大不等于看得见**：虚线框 `alpha=1.0` 但对比度只有 2.08:1，一样太淡。
  要按 WCAG 算对比度，别只看不透明度。
- **1px 不等于 1**：1.5 倍缩放下 `getComputedStyle` 返回 `0.667px`，
  那是设备像素比换算，不是 bug。断言要写 `边框宽 × dpr ≈ 1`。

**每轮涉及视觉的修复，证据必须是量出来的数字**（脚本 + 断言 + 日志），
不能是"我试了没问题"。

### 21.3 打包版验包怎么跑

```powershell
# 1) 从 Release 下载真实的包（不是本地 build 的）
$env:HTTPS_PROXY='http://127.0.0.1:7890'   # 没代理的话 GitHub 大文件下不动
curl.exe -L -o .tmp\pkg033\pkg.exe `
  https://github.com/Mike666wq/tomato-clock/releases/download/v0.3.3/tomato-clock-0.3.3-portable-single.exe

# 2) 起包（独立 userData + 独立 CDP 端口）
#    参数 pkg-profile-033 是用来认进程的标记，见下面那个坑
Start-Process .tmp\pkg033\pkg.exe `
  -ArgumentList '--user-data-dir=<项目>\.tmp\pkg033\data','--remote-debugging-port=9224','pkg-profile-033'

# 3) 跑同一套旅程
$env:CDP_PORT='9224'; $env:E2E_SKIP_DEV='1'
$env:E2E_DATA='<项目>\.tmp\pkg033\data\data.json'
$env:E2E_RESIZE_PROC='番茄钟'      # 打包版的进程名就是产品名
$env:E2E_RESIZE_CMD='pkg-profile-033'
node scripts\e2e-journey.mjs
```

**打包版跑出来的项数会少一个**：`D4 跨零点` 按预期 **SKIP** ——
打包版里本来就不该有开发期的时钟注入口子，跳过是对的。

日志留在 `docs/logs/e2e-journey-packaged-0.3.3.log`。

#### 打包版验包的两个坑（都踩过）

| 坑 | 现象 | 处理 |
|---|---|---|
| **进程名不是文件名** | 传 `-ProcessName pkg` 找不到进程，D2 那项 FAIL | 打包版的进程名是**产品名**「番茄钟」，不是 exe 文件名。查实际进程名：<br>`Get-Process \| Where-Object { $_.Path -like '*pkg033*' } \| Select-Object ProcessName` |
| **机器上同时跑着用户的正式版** | 拖窗口会拖错窗口，可能把用户那个关了 | 靠**命令行片段**只认被测的那个：`-CmdLineLike pkg-profile-033`。<br>收尾只 kill 带这个片段的进程，**用户的正式版一个字都不动** |

> 顺带：`E:\tomato-clock\pomodoro\番茄钟.exe` 是用户自己装的那份，
> 验包期间**不要动它**。

## 二十二、三条做法（2026-11-23 v0.6.3 收尾时立的，长期生效）

这三条不是一次性任务，是**以后每轮都照着办**的做法。

### 22.1 口述的具体参数一律当"意图"，不当"指标"

**意图是"要达到什么效果"，指标得自己量出来。**

肥鱼说「虚线提到 `--line` 的正常不透明度」——那是拍脑袋给的值。
量下来 `--line` 满不透明在纸底上只有 **1.20:1**，等于还是看不见。
于是没有照抄，改成按 WCAG 目标（≥3:1）反推，最后落在 3.32 / 4.18 / 3.28。

**所以**：别人（肥鱼或用户）口述的**效果**照做，
口述的**具体数值**要当成"方向"，自己量出能达成那个效果的指标。

数字要么量出来，要么说明为什么不能量 —— 不能照抄一个看起来合理的值。

### 22.2 "被挡住/被切掉"的问题，先量挡人的那个元素的实际尺寸

统计页底部被导航栏切掉。肥鱼的说法是「底部留 80px」，
但**导航栏在三套主题下高度根本不一样**（纸感 37、霓虹 50、系统感 54）。
照着 80px 写死的话：纸感下空出一大块，霓虹下还是切。

**根治办法是量出导航栏的实际高度**（`ResizeObserver` → CSS 变量 `--nav-h`），
而不是找一个"大概够"的常量。

**凡是"某个东西被另一个东西挡住/切掉"，先量后者的实际尺寸，别用常量。**

### 22.3 截断只能发生在"允许被截的那个元素"上

音乐行做"歌名左、歌手右"时，歌手那块一开始写的是 `flex: 0 1 auto`。
结果歌名很长时，两者按各自内容宽度分摊缩量，
`JINBAO` 被压成 25px 还要再省略一次 —— **你以为只截了一处，实际两处都在截**。

**规矩**：要保留的元素一律 `flex-shrink: 0`，
让截断只发生在明确允许被截的那个元素上（歌名 `flex: 1 1 auto; min-width: 0`）。

**宁可让歌名全截光，歌手也要完整。**

### 22.4 工具不能碰用户自己的环境

用户那台机器上跑着他自己装的正式版（`E:\tomato-clock\pomodoro\番茄钟.exe`）。
验包期间**全程没动它** —— 跑之前 5 个进程，跑之后还是那 5 个，PID 一字未变。

**我们的测试不能去碰用户的环境**：起实例用独立 `--user-data-dir`，
认进程用命令行片段，收尾只 kill 自己起的那一个。

## 二十三、断言成片失败，先怀疑环境（2026-11-23 晚，长期生效）

### 23.1 端到端一次 FAIL 15 项 —— 是数据目录对不上，不是程序坏

改完时间线的注释，跑一次端到端，**15 项 FAIL**：
S4 / S5 / S6 / S7 / D1 / D3 / D4 全红，看着像程序大面积回归。

实际原因：**开发版实例的 userData 和 e2e 脚本读的数据文件不是同一个**。

| | 路径 |
|---|---|
| 实例（我起的） | `POMODORO_USER_DATA=<项目>\.tmp\shot` → 程序写 `.tmp\shot\data.json` |
| 脚本（默认） | `E2E_DATA` 默认 `<项目>\.tmp\e2e\data.json` → 脚本读这个 |

两边各读各的文件，断言自然全错：界面显示 7 个、磁盘只有 1 条。

换成同一个 userData 重跑 → **33 项全过**。

### 23.2 两条做法

1. **e2e 与 measure 共用一个实例时，`E2E_DATA` 必须等于该实例 userData 下的 `data.json`。**
   两个脚本各自的默认值不一样（`.tmp\e2e` vs `.tmp\shot`），混用就会对不上。

2. **断言"成片"失败（≥5 项一起红）时，先怀疑环境，再怀疑程序。**
   真 bug 通常打中一处，成片失败多半是两边对不上。

   症状特征（见到就直接查路径，不用先读代码）：
   - 界面上的数与磁盘上的数对不上
   - 状态行读出来是 `undefined`
   - 主进程汇总比磁盘记录数大

   查法：把实例的 userData 和脚本的 `E2E_DATA` 两行路径并排看一眼。

### 23.3 按命令行片段认进程时，会把自己也匹配进去

收尾时用 `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*pkg-profile-035*' }`
来找自己的被测实例 —— 结果**这条命令自己的命令行里就含 "pkg-profile-035"**，
于是 runner 进程被 `Stop-Process` 干掉，命令直接报错退出（Job runner exited）。

**规矩**：按命令行片段筛进程时，
- 片段要是**这一轮独有的**（比如带时间戳的目录名），别用会出现在自己命令里的通用词；
- 更稳的是按**可执行文件路径**筛（`$_.ExecutablePath -like '*\release\win-unpacked\*'`），
  命令行片段只用来二次确认；
- 收尾前先 `Get-CimInstance` **列一遍**再 kill，别直接 kill。

### 23.4 打包版启动退出码 9 = `ELECTRON_RUN_AS_NODE` 残留

手工 `Start-Process` 打包版 exe 时退出码 **9**，怎么加参数都一样（连 `--no-sandbox` 都是 9）。
根因：环境里残留 `ELECTRON_RUN_AS_NODE=1`，exe 被当成 node 跑，
node 的 "bad option" 退出码正好是 **9** —— 看着像 Electron 拒绝参数，其实是认错程序了。

**规矩**：手工启动任何 Electron 打包产物前，先
`Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue`。
`scripts/dev.mjs` 自己会清，但**手动 Start-Process 不会**。

⚠ 还有一个更阴的版本：这个变量**设成空字符串不算清掉** ——
Chromium 认的是「这个变量存不存在」，空字符串照样算数。
要从 env 里**删掉**，不能设成空。

## 二十四、验证脚本的前置自检（2026-11-23 晚，长期生效）

### 24.1 为什么要有

肥鱼的原话：

> 「里头两个是同一个病 —— `ELECTRON_RUN_AS_NODE` 文档里写过还踩，
> 数据目录搞成两处一次 FAIL 15 项，都是**验证脚本没有前置自检，全靠人记文档**。
> 记忆会失手，脚本不会。给它加一道开跑前的自检，不过就 abort 并打印原因，
> 不许带病往下跑。」

**规矩**：验证脚本开跑前必须自检，**不过就 abort（退出码 1）并打印原因**，
不许"带病往下跑"。带病跑出来的 FAIL 是"测试环境坏了"，不是"程序坏了" —— 这个误判很贵。

### 24.2 三个新脚本

| 脚本 | 干什么 |
|---|---|
| `scripts/preflight.mjs` | 自检本体（被别的脚本 import） |
| `scripts/start-instance.mjs` | 统一起被测实例 + 写下清单 `.tmp/instance.json` |
| `scripts/stop-instance.mjs` | 收尾：按可执行文件路径**先列后杀** |

### 24.3 自检查什么

1. **数据目录一致**：`E2E_DATA` 必须等于 `<实例 userData>\data.json`，
   `E2E_SNAPSHOT` 必须等于 `<实例 userData>\running.json`。不一致直接停。
2. **清 `ELECTRON_RUN_AS_NODE`**：有残留就删掉并打印一行（残留会让 exe 被当 node 跑，退出码 9）。
3. **进程筛选方式**：禁止 `E2E_RESIZE_CMD`（按命令行片段筛），必须用
   `E2E_RESIZE_EXE`（按可执行文件路径通配）。
4. **端口对得上**：`CDP_PORT` 与清单里的端口不一致就停（连错实例 = 测了另一个程序）。

### 24.4 用法

```powershell
# 起实例（开发版）
node scripts\start-instance.mjs --dev --profile .tmp\e2e

# 跑旅程（参数照它打印的那行来）
$env:E2E_DATA='<项目>\.tmp\e2e\data.json'
$env:E2E_SNAPSHOT='<项目>\.tmp\e2e\running.json'
$env:E2E_RESIZE_EXE='*node_modules*electron*dist*electron.exe'
$env:CDP_PORT='9222'
node scripts\e2e-journey.mjs

# 收尾（先列后杀，只杀自己起的）
node scripts\stop-instance.mjs
```

打包版把 `--dev` 换成 `--exe "<打包产物路径>" --port 9224`。

### 24.5 实测拦下来的两例（证据）

**① 数据目录不是同一处**（这正是那 15 项 FAIL 的成因）：

```
[自检不通过] 端到端旅程：E2E_DATA 与被测实例的 userData 不是同一处
  E2E_DATA=C:\...\番茄钟\.tmp\shot\data.json
  实例 userData=C:\...\番茄钟\.tmp\e2e
  两者应该是同一个文件：C:\...\番茄钟\.tmp\e2e\data.json
  （两边各读各的文件 → 断言会成片失败，那是测试环境坏了，不是程序坏了）
  —— 带病不跑。修好上面这条再来。
```

**② 用了旧的按命令行片段筛开关**：

```
[自检不通过] 端到端旅程：E2E_RESIZE_CMD 是按命令行片段筛进程，已废弃
  按命令行片段筛会把「自己这条命令」也匹配进去（自杀过一次）。
  改用 E2E_RESIZE_EXE=<可执行文件路径通配>
```

自检放行后：端到端 **33 项全过**、布局测量 **18 项全过**。

### 24.6 进程筛选按路径：两个坑

1. **pnpm 的 electron 真实路径不在 `node_modules\electron\dist`**，
   而在 `node_modules\.pnpm\electron@45.4.1_...\node_modules\electron\dist\electron.exe`。
   通配要按这个写，否则一个都匹配不到（我第一次就写了错的，匹配数 0，还以为实例已经退了）。
2. **`resize-window.ps1` 的 `-CmdLineLike` 已废弃**：传了就报错退出（退出码 2），
   改用 `-ExePathLike`。
